# git.sr.ht SSH Push Pipeline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Enable `git clone`/`push` over SSH to `git.cirriform.au` repositories, authenticated by SSH keys registered in meta.sr.ht, without modifying terpsichore's host sshd.

**Architecture:** Run an sshd **inside the `srht-git` incus container** on the container's port 22, using SourceHut's unified dispatcher `sourcehut-ssh` as the `AuthorizedKeysCommand` (it validates the connecting key against meta.sr.ht over GraphQL and dispatches authorized git operations to `git.sr.ht-shell`). Expose it on the host via an incus `proxy` device mapping `terpsichore:2222 → srht-git:22`, so users push to `ssh://git@git.cirriform.au:2222/~user/repo`. The host's own sshd (port 22, admin access) is never touched.

**Tech Stack:** NixOS module (`modules/nixos/sourcehut/`), incus 6 (`proxy` device), Alpine `openssh` inside the container, SourceHut `sourcehut-ssh` + `git.sr.ht-shell`, meta.sr.ht GraphQL for key registration.

**Why Approach A (dedicated port):** `git.cirriform.au` resolves to terpsichore (`192.168.1.16`), where the host sshd already owns port 22 for admin access. A dedicated port routed straight into the container avoids any change to the host sshd (which carries lock-out risk).

## Task 2: Provision sshd + sourcehut-ssh dispatch inside the git container

**Files:**
- Modify: `modules/nixos/sourcehut/containers.nix` (the `mkContainerService` `script`, in the provisioning section that runs after `apk add ${name}.sr.ht`)

- [ ] **Step 1: Add an SSH-provisioning block, guarded to the git service**

In `containers.nix`, add a Nix `let` binding near `serviceExtraIni` (around line 28):

```nix
      sshProvision =
        if name == "git" then
          ''
            incus exec ${containerName} -- sh -c '
              set -e
              apk add --no-cache openssh
              ssh-keygen -A
              # Unlock the git user so sshd will accept it (no password login; key only)
              passwd -u git 2>/dev/null || true
              # System-wide git safe.directory for the repo store
              git config --system --replace-all safe.directory "/var/lib/git/*"
              # sshd config: hand every auth to sourcehut-ssh, allow SRHT_* env
              cat > /etc/ssh/sshd_config.d/10-sourcehut.conf <<SSHD
            AuthorizedKeysCommand /usr/bin/sourcehut-ssh "%u" "%h" "%t" "%k"
            AuthorizedKeysCommandUser root
            PermitUserEnvironment SRHT_*
            PasswordAuthentication no
            KbdInteractiveAuthentication no
            AllowUsers git
            SSHD
              mkdir -p /var/log/git.sr.ht
              chown git:git /var/log/git.sr.ht
              rc-update add sshd default
              rc-service sshd restart
            '
          ''
        else
          "";
```

- [ ] **Step 2: Invoke the block in the provisioning script**

In the same `script`, immediately after the `apk add ${name}.sr.ht` `incus exec` block and before the config.ini generation, insert:

## Task 3: Expose the container sshd on the host via an incus proxy device

**Files:**
- Modify: `modules/nixos/sourcehut/containers.nix` (extend the per-service `extraConfig`, which already runs incus device commands for `builds`)

- [ ] **Step 1: Add the proxy device for the git container**

In `containers.nix`, extend `extraConfig` so the `git` service adds a proxy device (this runs inside the `if ! incus info` creation block; it is also safe to re-assert). Change the `extraConfig` binding to cover `git`:

```nix
      extraConfig =
        if name == "builds" then
          ''
            incus config set ${containerName} security.nesting=true
            incus config device add ${containerName} kvm unix-char path=/dev/kvm 2>/dev/null || true
          ''
        else if name == "git" then
          ''
            incus config device add ${containerName} sshproxy proxy \
              listen=tcp:0.0.0.0:2222 connect=tcp:127.0.0.1:22 2>/dev/null || true
          ''
        else
          "";
```

Note: `extraConfig` currently only runs on container **creation**. To ensure the device is present on the already-existing container without recreating it, also add an idempotent assertion in the main script (after `incus start`):

```nix
                ${lib.optionalString (name == "git") ''
                  incus config device get ${containerName} sshproxy listen >/dev/null 2>&1 \
                    || incus config device add ${containerName} sshproxy proxy \
                         listen=tcp:0.0.0.0:2222 connect=tcp:127.0.0.1:22
                ''}
```

## Open questions / risks

- **Dispatch config exact form** — resolved in Task 1; do not proceed to Task 4 config until confirmed.
- **Non-standard port** — `:2222` must be appended to clone URLs; acceptable trade-off for not touching host sshd. If a standard-port experience is later desired, revisit Approach B/C (host `git` user delegating into the container, or a bridged container IP), noting Approach B's host-sshd lock-out risk.
- **WAN access** — this plan enables LAN push (git.cirriform.au → 192.168.1.16). External push additionally requires forwarding `2222` at the edge router; out of scope here.
- **Builds trigger** — a working push through `git.sr.ht-shell` runs the repo hooks; auto-submitting builds still additionally requires the git→builds integration (separate task).
